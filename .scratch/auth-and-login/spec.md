## 1. 问题陈述

从使用者视角看：

- 现在任何人打开系统都能直接进入文档管理与知识库对话，系统不知道「你是谁」，前端只能固定塞一个调试用的用户标识。想限制「谁可以管理文档、谁可以管理账号、谁只能聊天」这件事，当前无法做到。
- 侧边栏只有两个平级入口。再加功能就只能继续往一排里塞，既没有归类，也没有「设置」这类天然属于同一组的页面。
- 想停用某个人的访问，只能让他自己别用；想改口令、想加人，都没有入口。

从维护者视角看：

- 身份只是一个可伪造的请求头，任何知道格式的人都能冒充他人读写别人的会话。
- 文档管理、评测等接口当前完全无鉴权，属于随时会暴露的运维风险。
- 前端与后端各自维护一套身份约定（固定常量 + 请求头），没有单一事实源。

---

## 2. 解决方案

引入真实账户体系与角色权限，把身份从前端伪造的请求头改为服务端签发的会话令牌：

1. **登录**：账号 + 口令登录，服务端校验后签发不透明令牌；前端持有令牌并在每次请求的 `Authorization` 头中携带。
2. **权限**：角色是可管理的数据，角色由固定权限点组成，账户可挂多个角色，权限取并集；内置「系统管理员」角色隐式拥有全部权限。
3. **页面**：新增登录页、账户管理页、角色管理页；侧边栏改为「知识库」「系统设置」两个一级分组，原有两个页面归入「知识库」。
4. **收敛身份**：`user_id` 统一为账户表主键（字符串 UUID），会话归属、认证上下文、前端身份传递全链路只用它；删除旧的请求头注入与前端固定用户常量，不保留两套并存。
5. **存量数据**：启动时把历史调试会话归属迁移到初始管理员，幂等执行、条件不满足时跳过。

## 3. 用户故事

### 登录与登出

1. 作为未登录访问者，我想看到登录页而不是被直接放进业务页面，以便知道需要先证明身份。
2. 作为访问者，我想在口令输错时看到「用户名或密码错误」这一条统一提示，以便不会通过提示差异反推出某个账号是否存在。
3. 作为访问者，我想在登录成功后回到我原本要去的页面，以便不用登录后再自己找一遍入口。
4. 作为已登录账户，我想在访问登录页时被送回业务首页，以便不会出现「已经登录还在看登录页」的困惑。
5. 作为已登录账户，我想在侧边栏底部看到自己的用户名并能一键退出，以便共用电脑时能主动结束会话。
6. 作为已登录账户，我想在令牌过期后被送回登录页并保留原目标地址，以便过期后继续操作不迷路。
7. 作为已登录账户，我想在权限不足时看到「无访问权限」而不是被踢回登录页，以便不会反复输入正确口令却进不去。

### 导航结构

8. 作为已登录账户，我想在侧边栏看到「知识库」与「系统设置」两个一级分组，以便按用途找到页面而不是记路径。
9. 作为已登录账户，我想在「知识库」下看到「文档管理」「知识库对话」，以便原有的两个功能位置不变、只是多了一层归类。
10. 作为已登录账户，我想在「系统设置」下看到「账户管理」「角色管理」，以便管理入口集中在一处。
11. 作为已登录账户，我想在进入某个子页时看到对应一级自动展开并高亮，以便始终知道自己在哪。

### 账户管理

27. 作为角色管理员，我想看到角色列表（名称、描述、权限点数、引用账户数、是否内置），以便知道每个角色影响多少人。
28. 作为角色管理员，我想新建角色并勾选权限点，以便组合出「文档只读」「知识库读者」这类最小权限集合。
29. 作为角色管理员，我想编辑自定义角色的名称、描述与权限点，以便随业务调整授权。
30. 作为角色管理员，我想删除没有被任何账户引用的自定义角色，以便清理不再使用的角色。
31. 作为角色管理员，我想在删除仍被引用的角色时被拒绝并看到引用数量，以便先解绑再删。
32. 作为角色管理员，我想让内置「系统管理员」不可改名、不可改权限、不可删除，以便永远不会因为误操作把管理入口锁死。
33. 作为角色管理员，我想让权限点的勾选结果就是接口的真实校验依据，以便「菜单看得见」和「接口调得通」不会出现两套真相。

### 安全与治理

34. 作为系统维护者，我想让账户口令只以 BCrypt 摘要形式落库，以便数据库被读取也拿不到明文口令。
35. 作为系统维护者，我想让令牌在数据库中只以摘要形式存在，以便库被读取也拿不到可用令牌。
36. 作为系统维护者，我想让未登录请求得到统一格式的 401 JSON（包括流式问答接口），以便前端与脚本能一致处理。
37. 作为系统维护者，我想让登录失败与令牌失效虽然都是 401 但文案与前端处理不同，以便登录页只报错、业务页才跳登录。
38. 作为部署者，我想只通过环境变量提供一个初始管理员口令就能在全新环境启动，以便不需要手工写 SQL 才能进系统。
39. 作为部署者，我想在没有提供初始管理员口令时系统仍能启动并只记录一条警告，以便不会因为漏配变量导致服务起不来。
40. 作为升级已有环境的维护者，我想让历史调试会话自动归属到初始管理员，以便升级后旧数据不是凭空消失。
41. 作为升级已有环境的维护者，我想让这段迁移重复执行也不会产生副作用，以便重启不会重复改写。
42. 作为账户管理员，我想在无法禁用或降权最后一个具备账户管理能力的账户时收到明确拒绝，以便不会把所有人锁在门外。
43. 作为使用者，我想在角色权限变化后，下一次请求就按新权限生效，以便调整授权不需要重启服务。

## 4. 实现决策

### 4.1 模块划分

| 模块 | 职责 |
|---|---|
| 账户领域 | 登录、登出、当前账户；账户增改查与口令、状态；角色增删改查；权限点目录；启动引导与存量迁移编排 |
| 公共认证层 | 认证拦截器：解析并校验令牌，把账户标识写入请求上下文；替换原有身份拦截器 |
| 公共常量层 | 权限点枚举（`code` + `desc` 双字段）、账户状态与角色内置标记等字面量、新增错误码 |
| 会话领域 | 现有会话查询、写入、删除逻辑不改，只是 `user_id` 的来源改为认证上下文 |
| 前端认证层 | 认证上下文（令牌读写、登录/登出、401 监听）、路由守卫、登录页 |
| 前端设置页 | 账户管理页、角色管理页 |
| 前端外壳 | 导航分组模型、展开与高亮、面包屑、按权限过滤 |

新增依赖只有一个：`spring-security-crypto`（仅使用 BCrypt 编码器）。不引入 `spring-boot-starter-security`，前端不新增任何依赖。

### 4.2 数据模型

新增 5 张表，均带表与列注释；时间字段沿用 `create_time` / `update_time` 口径：

| 表 | 关键内容 | 约束要点 |
|---|---|---|
| 账户表 | `user_id`（TEXT 主键，UUID v4）、`username`、`display_name`、`password_hash`、`status`、时间字段 | `username` 唯一且不区分大小写（`lower()` 函数唯一索引）；`status` 取 `ENABLED` / `DISABLED` |
| 角色表 | `role_id`（TEXT 主键）、`name`、`description`、`builtin`、时间字段 | `name` 唯一且不区分大小写（`lower()` 函数唯一索引），与账户表口径一致 |
| 账户角色关联表 | `user_id` + `role_id` 复合主键 | 两列均外键；角色侧删除限制，账户侧级联 |
| 角色权限关联表 | `role_id` + `permission_code` 复合主键 | 只存权限码字符串，不建权限点表；权限点目录由代码枚举提供 |
| 会话表 | `token_hash` 主键、`user_id`、`expire_time`、`create_time` | 只存令牌摘要；账户侧级联删除；按 `user_id` 建索引 |

现有会话表的 `user_id` **类型不变**（TEXT），值改为账户表主键；**不新增外键**，理由：存量数据在迁移完成前不满足约束，且本期不提供删除账户能力，以列注释声明其语义。

### 4.3 认证与会话

- 令牌：`SecureRandom` 生成 32 字节，Base64URL 编码后返回前端；数据库只存其 SHA-256 摘要。
- 校验顺序：头存在 → `Bearer ` 前缀 → 摘要查表 → 未过期 → 账户为启用状态。任一步失败即 401。
- 有效期固定 7 天，不滑动续期；允许多设备并存。
- 登出只删除当前令牌对应会话。
- 登录成功时顺带删除该账户已过期的会话行，不做定时清理任务。
- 重置他人口令、禁用账户、修改自己的口令：失效该账户相应会话（改自己口令保留当前令牌）。
- 拦截范围：所有 `/api/**` 需登录，仅登录接口与健康检查匿名。

### 4.4 权限模型

- 权限点固定 5 个，写在代码枚举中，同时作为角色页的勾选目录：查看文档、维护文档、使用知识库对话、管理账户、管理角色。
- 每张页面声明所需权限点；菜单可见性由「该组下是否有任一可见子页」推导，不单独存菜单可见字段。
- 账户可挂多个角色，权限取并集。
- 内置「系统管理员」角色在判定时短路为拥有全部权限点，不依赖关联表，确保新增权限点自动生效且不会锁死。
- 权限在每次请求时计算，不做进程内缓存；角色调整下一次请求即生效。

### 4.5 接口契约

统一响应 `{code, msg, data}`，时间格式 `YYYY-MM-DD HH:mm:ss`。

| 分组 | 接口 | 说明 |
|---|---|---|
| 认证 | 登录、登出、当前账户 | 登录返回令牌、到期时间与账户信息（含角色与权限点列表）；当前账户返回同一账户结构 |
| 账户 | 列表、新建、改显示名与角色、重置他人口令、改自己口令、改状态 | 改自己口令仅需登录，其余需「管理账户」权限 |
| 角色 | 列表、新建、编辑、删除 | 列表对「管理账户」权限也开放，供账户页选择角色；新建/编辑/删除需「管理角色」权限 |
| 权限点 | 权限点目录 | 需「管理角色」权限 |

关键行为：

- 口令规则唯一口径：最少 8 个字符（按 Unicode 码点计），最多 72 个**字节**（按 UTF-8 计）；超限直接 400，不做截断后放行。
- 新增账户必须至少指定一个角色；改名、改角色、改状态均返回更新后的账户条目。
- 角色删除：内置角色拒绝；被引用时拒绝并返回引用账户数。
- 用户名与角色名比较均不区分大小写。
- 路由顺序：改自己口令的固定路径必须排在按账户标识的改口令路径之前匹配，避免固定段被当作账户标识。

### 4.6 鉴权映射

| 既有接口 | 所需权限点 |
|---|---|
| 文档查询、切片、检索测试 | 查看文档 |
| 文档上传、重建、删除 | 维护文档 |
| 流式问答、会话列表/历史/删除 | 使用知识库对话 |
| 抽取、起草、评测 | 仅需登录（无页面入口） |

鉴权在拦截器中完成：失败发生在流式接口返回响应体之前，因此 401/403 是普通 JSON，不是事件流。

### 4.7 错误语义

| 场景 | HTTP 与错误码 | 文案 | 前端处理 |
|---|---|---|---|
| 登录凭据错误（账户不存在 / 口令错 / 已禁用） | 401，`UNAUTHORIZED` | 用户名或密码错误 | 登录页就地展示，不清令牌、不跳转 |
| 受保护接口令牌缺失 / 非法 / 过期 / 账户禁用 | 401，`UNAUTHORIZED` | 登录已失效，请重新登录 | 清令牌并跳登录 |
| 已登录但缺权限点 | 403，`FORBIDDEN` | 无访问权限 | 页面提示，不跳登录 |
| 报文字段缺失或类型错误 | 400，`PARAM_INVALID` | 具体字段说明 | 表单提示 |
| 用户名已存在 | 409，`USERNAME_EXISTS` | 用户名已存在 | 表单提示 |
| 角色名已存在 | 409，`ROLE_NAME_EXISTS` | 角色名已存在 | 表单提示 |
| 角色仍被引用 | 409，`ROLE_IN_USE` | 角色仍被 N 个账户使用 | 列表提示 |
| 内置角色被改名/改权限/删除 | 400，`ROLE_PROTECTED` | 内置角色不允许修改 | 入口置灰 + 后端兜底 |

`PARAM_INVALID` 只用于格式问题，不用于凭据错误；登录接口与受保护接口虽同为 401，但入口、文案、前端处理三者必须区分。

### 4.8 硬约束（后端强制）

1. 不能禁用自己。
2. 不能对最后一个具备账户管理能力的账户做禁用，也不能以任何方式移除其管理能力；判定按操作完成后的系统状态计算，且必须在「改状态」与「改角色」两个入口都校验。
3. 内置角色不可删除、不可改名、不可改权限。
4. 自定义角色仍有账户引用时不可删除。
5. 用户名、角色名唯一且不区分大小写。

### 4.9 前端行为

- 认证上下文负责令牌存取、登录/登出、监听 401 事件；接口层在 401 时只清令牌并派发事件，不直接依赖路由，由上下文统一跳转。
- 路由守卫包裹业务外壳内的所有页面；登录页不套外壳、不进侧边栏。
- 未登录访问受保护路由时记录原路径，登录成功回跳；回跳地址只接受站内相对路径。
- 导航以分组模型描述（一级：标题、图标、子项；子项：路径、所需权限点）；渲染时按当前账户权限过滤，自动展开所在组。
- 面包屑由当前路由反查分组得到，不再写死文案。
- `VITE_USE_MOCK=true` 时使用本地假登录与内存假数据（含全量权限），保证前端可独立开发。
- 删除前端固定用户标识常量，身份只来自登录结果。

### 4.10 启动引导与存量迁移

顺序：

1. 建表（新库直接生效）。
2. 确保内置「系统管理员」角色存在。
3. 按环境变量创建初始管理员并绑定内置角色（用户名默认 `admin`；口令无默认值）。
4. 将历史调试会话归属迁移到初始管理员。

迁移规则：

- 一条带 `WHERE user_id = 'dev-user-001'` 的更新语句，幂等性由条件本身保证（第二次命中 0 行）。
- 初始管理员未创建成功时整段跳过，只记录一条警告。
- 迁移语句归属会话领域，由启动引导经服务调用，不跨层直连数据源；不放进建表脚本（建表脚本只在新库执行一次，那时管理员尚不存在）。
- 已知后果：若某台环境的历史会话先被清理、之后才补管理员，这批数据不会二次迁移。

## 5. 测试决策

### 5.1 什么算好测试

只验证**对外可观察行为**：HTTP 状态码与响应体形状、SSE 事件序列、数据库最终状态、页面可见元素与跳转结果。不验证私有方法、不验证内部调用次数、不依赖实现顺序。

### 5.2 采用的测试缝（请评审时确认）

尽量复用现有缝，不新增测试基础设施，理想数量为两个：

1. **后端最高缝：HTTP 接口层**。用现有 `standaloneSetup` + 真实认证拦截器的控制器测试方式，覆盖 401/403/400/409 语义、账户与角色接口的入出参、流式接口在鉴权失败时返回普通 JSON。
2. **前端最高缝：页面层**。用 Testing Library 渲染真实路由与外壳，配合 mock API 覆盖登录、守卫、菜单过滤与两个设置页；不断言样式类名。

服务层作为第二层缝，仅用于无法通过 HTTP 简洁覆盖的纯逻辑：口令长度与哈希、令牌摘要、权限并集与内置短路、硬约束判定。

### 5.3 各模块测试安排

| 模块 | 测试方式 | 先例 |
|---|---|---|
| 认证拦截器 | 控制器测试中带/不带令牌、过期令牌、禁用账户 | 现有身份拦截器的控制器测试 |
| 登录/登出 | 控制器测试：成功、三类凭据错误文案一致、登出后令牌失效 | 现有控制器契约测试 |
| 账户管理 | 控制器测试 + 服务层单测：口令规则、用户名重复、五条硬约束 | 现有服务层单测 |
| 角色管理 | 控制器测试 + 服务层单测：内置保护、引用计数、权限码解析拒绝未知值 | 现有枚举解析测试 |
| 权限判定 | 服务层单测：多角色并集、内置短路、无权限返回 403 | 现有策略/服务单测 |
| 数据访问 | Mapper XML 可解析性契约测试、建表脚本契约测试 | 现有 Mapper 契约测试 |
| 启动引导 | 单测：缺口令跳过、已存在不重复创建、迁移幂等 | 现有服务单测 |
| 前端认证 | 页面层测试：未登录跳转、登录回跳、401 登出、403 提示 | 现有页面测试 |
| 前端导航 | 页面层测试：分组渲染、按权限过滤、面包屑、窄屏行为 | 现有外壳测试 |
| 前端设置页 | 页面层测试：列表渲染、表单校验、内置角色只读 | 现有页面测试 |

### 5.4 不做的测试

- 默认 `mvn test` 档不跑真库集成测试：按 ADR-0017（已取代 ADR-0006 中「真库验证方式」一节），真库测试用 Testcontainers 起 `pgvector/pgvector:pg16`，测试类标 `@Tag("docker")`，`mvn test` 默认排除该标签，`mvn test -Pintegration-tests` 放开；无 Docker 的机器自动跳过、不判失败。账户、角色、会话相关表的约束与存量迁移结果属于此类真库验证范围；纯逻辑与接口契约仍在默认档覆盖。
- 不测 BCrypt 算法本身、不测第三方库内部行为。
- 不测 Tailwind 样式与像素布局。

### 5.5 验收对照

沿用 PRD 第 11 节的 9 条验收，逐条在评审后映射到上述测试或手工步骤；全量后端测试、前端测试、类型检查与构建必须全绿。
