# 11: 失败矩阵与降级收口

**阶段:** P3 失败与预算
**Blocked by:** 10、03
**Status:** ready-for-agent

**范围:** 把散落的失败路径收成一张可验证的矩阵：路由失败、计划弃用、步骤失败、预算耗尽、合成异常、客户端断开、线程池拒绝。

**要做的事:** 每种异常都有确定的用户可见结果、落库状态与收尾事件，不会出现「卡住不结束」或「结束状态互相矛盾」。

**涉及文件/类:** `QaServiceImpl`、`PlanAndExecuteService`、全局异常处理、消息终态写入。

- [ ] 路由失败类全部降级 `KNOWLEDGE`，不发 `error`，消息 `DONE`
- [ ] 计划弃用发 `plan(degraded=true, goal="", steps=[])` 后按 `KNOWLEDGE` 执行
- [ ] 步骤失败/降级继续执行，整轮仍 `DONE`
- [ ] 预算提前收尾见票 10 的两条分支
- [ ] 合成超时/异常 → `error` + `FAILED`，保留已推正文
- [ ] 客户端断开 → `STOPPED`，会话锁释放，不重复落库
- [ ] 线程池拒绝 → 同步失败响应，消息 `FAILED`
- [ ] 同步边界：`400` / `404` / `409` 在返回 emitter 之前抛出，不进 SSE
- [ ] 整合测试逐行覆盖矩阵；断言不会出现「`done` 与 `FAILED` 同时存在」

**不做什么:** 不做自动重试整轮；不做补偿任务；不新增错误码体系之外的字段。
