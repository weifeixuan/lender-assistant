# ADR-0020：滚动摘要覆盖边界记 roundId，不记轮数

- 状态：已采纳（需求定稿，代码未实施）
- 相关：`docs/prd/conversation-rolling-summary.md`、`docs/adr/0008-round-id-as-turn-key.md`、`docs/schema.sql`

## 背景

会话级滚动摘要需要回答一个问题：「摘要覆盖到哪一轮为止」。直觉答案是用配置数字表达——「最近 6 轮之前」，但这个口径是错的：

- 回放窗口实际保留轮数 = min(轮数上限, 字符预算允许的轮数)。正常 RAG 回答每轮 500–800 字符，2000 字符预算下窗口往往只保 2~3 轮——被裁可能发生在第 4 轮而非第 7 轮；
- 窗口参数（轮数、字符）是环境变量，随时可调；按数字记录的摘要边界会在调参后与实际窗口错位，且错位是静默的：摘要照常注入，只是盖不住真实被裁的轮次。

## 决策

- `conversation` 表存两列：`summary`（摘要正文）与 `summary_boundary_round_id`（被摘要覆盖的**最后一个完整轮**的 `roundId`），同写同空；边界是轮次身份，不是轮数数字。
- 边界每次触发检测时**从 DB 消息实算**，禁止任何引用配置数字的分支。
- 依赖不变式：被裁轮次恒为完整轮序列的**最旧连续前缀**（轮数上限与字符上限的丢弃方向一致，FAILED / rule 轮本就不在完整轮序列内）。这是「单边界」足以表达覆盖范围的前提。
- 消息全量落库、窗口只是回放策略（ADR-0008 的轮次结构之上）：窗口调大时旧轮自然回归，靠注入条件「边界轮严格早于窗口最旧轮」防重复注入，**不做摘要回滚或重算**；窗口调小产生的间隙轮，下次合并自动补齐。

## 影响

- 滚动合并输入可精确增量：现有摘要 + 边界之后的被裁轮原文，不重放全会话。
- 窗口参数任何方向调整都不需要摘要迁移或数据订正，最多多一次合并调用。
- 注入条件引入「摘要暂缺」状态（窗口扩大后的重叠期内本轮不注入），属可接受的宁缺勿重。
- 若将来引入「按主题裁剪」「非连续丢弃」等回放策略，前缀不变式失效，需要改为覆盖集合表达，而不是在单边界上打补丁。
