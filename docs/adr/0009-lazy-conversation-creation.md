# ADR-0009：会话懒创建，空会话不落库

- 状态：已采纳
- 相关：`docs/requirements/multi-turn-backend.md §1.3 / §4.4`、`docs/requirements/multi-turn-frontend.md §4.3`、`.scratch/multi-turn-conversations/spec.md`

## 背景

原方案是显式 `POST /api/conversations`：用户点「新建会话」就先在服务端创建一条记录，再进入问答。实际使用中出现两个问题：

- 用户点了新建，却在旧会话里继续聊天，服务端留下一条没有首问的空会话；
- 空会话进入列表，既没有标题也不可辨认，用户只能手动删除，列表被噪声污染。

空会话在数据层也没有可用的语义：没有首问就没有标题、没有轮次、没有可回放内容。

## 决策

- 删除显式新建会话接口，会话只在**首问受理时**由后端创建；
- 前端「新对话」只进入本地草稿态，不调用接口、不占列表；
- 首问请求不携带 `conversationId`，后端在受理线程内生成 `conversationId`、`roundId`、用户与助手消息 id，并通过 SSE 首个 `meta` 事件回传；
- 数据库中不存在「没有首问的会话」这种记录。

## 影响

- 列表里每条会话都至少有一轮提问，标题可直接取首问正文前 20 个字符，不再需要「未命名会话」占位。
- 前端必须在收到 `meta` 后才能把草稿转正；首问失败时草稿仍留在本地，不产生服务端垃圾数据。
- 首问超时但后端已创建会话时，前端重发会产生重复会话——这是本阶段接受的已知限制，后续用 `clientRequestId` 做幂等收敛。
- 草稿态刷新或关闭页面即丢失，不提供恢复，因为服务端从未持有它。
