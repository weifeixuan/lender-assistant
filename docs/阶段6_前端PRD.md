# PRD：Lender Assistant 知识库前端（文档管理 + 知识库对话）

**文档性质**：新模块需求｜**实现形态**：React 单页应用，替换现有 `static/index.html` 操作台中的文档与问答部分
**交互参考**：[lender-kb-ui.html](lender-kb-ui.html) 方案 A 的整体结构 + 方案 C 的检索过程侧栏（原型中的"页码 / token / 解析中状态"均为占位，**以本文为准**）

---

## 1. 背景与目标

现有操作台把上传、文档列表、检索测试、问答、字段映射抽取、代码草稿六件事堆在一张长页面上。文档入库后，使用者无法确认系统到底把文件切成了什么样，只能靠"检索测试"反推；问答区只给出答案，无法看到召回了哪些内容、为什么是这几条，答错时无法判断是切分问题还是检索问题。

本次产品决定：把"文档"与"对话"拆成两个独立页面，并把**切分结果**和**检索依据**变成一等公民。目标是使用者在两个地方各拿到一个可验证的结论：

- 文档管理页：这份文件被切成了 N 条，每一条长什么样、属于哪个章节，能逐条读完。
- 对话页：这个答案引用了哪几条切片，每条是向量命中还是关键词命中，融合后排在什么位置。

完成标准（可观察）：看完一份文档的全部切片后，使用者能指出切分是否把一段完整规则切断了；读完一次回答后，使用者能判断答案是被哪条切片支撑的。

## 2. 范围

**P0（本期必须完成）**

1. 文档上传入库，含覆盖重建的确认
2. 文档列表（文档名、切片数、最近入库时间）
3. 切片浏览：分页、展开原文、复制
4. 知识库对话：单轮提问、流式回答、来源引用可点击
5. 检索过程侧栏：双通道召回与融合排序的可视化
6. 两页导航与整体布局

**明确不做**

- 不做"字段映射抽取""代码草稿生成"的迁移入口，连置灰入口也不留（该能力继续只在旧操作台可用）
- 不做多轮对话上下文、会话持久化、历史会话列表、导出、答案打分反馈
- 不做原文件预览、下载、文档重命名
- 不做按文档范围过滤检索、不做鉴权与多用户权限

**P1（后续评估，不在本期）**

- 按文档范围限定检索（"只在这 2 份文档里问"）
- 切片的重新切分与手工修正

## 3. 产品模型与术语

| 术语 | 定义 |
|---|---|
| 文档 | 一次入库的单位，由使用者上传的文件产生；以 `docId` 唯一标识，同名 `docId` 再次上传即整体覆盖 |
| 文档名 | 原始文件名去掉扩展名后的标题，用于展示与引用 |
| 原始文件名 | 带扩展名的上传文件名，仅作辅助信息展示 |
| 切片 | 文档切分后的最小单元，有序号（从 0 起）、章节路径（如「3 日末文件 > 3.2 逾期文件格式」）、字符数、原文 |
| 字符数 | 解析后纯文本的字符数，**不是** token 数 |
| 召回 | 一次提问时，系统从全部切片中选出的若干条，按"向量通道 / 关键词通道 / 双通道命中"分类 |
| 来源 | 送入回答生成的召回结果，按 1..N 编号；回答正文中写作【来源N】 |

系统不存在"解析中 / 待解析"这类文档状态：上传请求会一直挂到全部处理完成才返回，返回即是最终结果。因此界面上**不出现任何文档状态标签、进度百分比**。

## 4. 功能需求

### FR-01 文档上传入库

**目的**：把一份文件变成可检索的切片，并让使用者当场看到处理结果。

**入口**：文档管理页右上「上传文档」；打开后是一个面板，含拖拽区与三个字段。

**字段与规则**

| 字段 | 必填 | 默认 | 规则 |
|---|---|---|---|
| 文件 | 是 | — | 单文件，仅允许 docx / txt / md（以服务端支持的类型为准） |
| docId | 是 | 由文件名生成 | 小写；空格与非法字符转为 `_`；仅 `a-z0-9_-`，长度 ≤ 64；可手动修改 |
| 覆盖确认 | 条件触发 | 隐藏 | 当 docId 与已有文档相同时出现，必须勾选确认后才能提交 |

**处理与反馈**

1. 提交后按钮进入等待态，输入区锁定，显示四段式文案并逐段点亮：解析 → 切分 → 向量化 → 入库；每段显示已用时间，整体显示总计时。系统不提供真实百分比，**不得**伪造进度条。
2. 返回后展示结果摘要：切片数、平均字符数、四段耗时、向量化模型名。
3. 列表刷新，并把该文档置顶/定位到该行。

**覆盖重建**：确认文案必须写明"将删除该 docId 下原有的 N 个切片，重建后旧内容不可恢复"。覆盖成功后展示"已重建 N 个切片"。

**异常**

- 不支持的文件类型 → 面板内就地提示，不提交。
- docId 格式非法 → 就地提示，不提交。
- 服务端处理失败（嵌入超时、数据库异常等）→ 面板内展示服务端返回的可读原因，保留已选文件与 docId，提供「重试」。
- 上传期间不允许关闭面板或切换页面（避免半程状态误判）；若使用者强制刷新，视为未上传。

### FR-02 文档列表

**目的**：作为切片浏览的入口，同时给出知识库规模。

**布局**：表格。列顺序与内容：

| 列 | 内容 |
|---|---|
| 文档 | 类型图标 + 文档名（主）+ 原始文件名与总字符数（次） |
| 切片数 | 数字，右对齐 |
| 最近入库时间 | `YYYY-MM-DD HH:mm`，覆盖重建会刷新该时间 |
| 操作 | 「查看切片」「删除」 |

**规则**

- 默认按最近入库时间倒序。
- 表格上方提供本地过滤输入框，按文档名或 docId 即时过滤当前列表；**不提供全局搜索**（系统不支持搜切片）。
- 页面顶部概览条：文档总数、切片总数、最近一次入库距今时长。
- 空态：无任何文档时展示上传引导，不显示空表头。
- 删除：二次确认，文案写明"删除后该文档的 N 个切片一并移除且不可恢复"；成功后行移除、概要进一步刷新；失败保留行并提示原因。

### FR-03 切片浏览

**目的**：这是本期的核心验收点——让使用者读完一份文档的全部切片，判断切分是否合理。

**触发与布局**：点击表格行或「查看切片」，右侧滑出抽屉（宽约 460），列表不被遮挡的部分保持可操作。抽屉可分页滚动。

**抽屉头部**：文档名、原始文件名、切片总数、总字符数、最近入库时间。

**切片条目**（按序号升序）

| 元素 | 规则 |
|---|---|
| 序号 | `#0` 起，等宽数字 |
| 章节路径 | 原样展示；为空时显示「（无小节）」 |
| 字符数 | `123 字符`，与"字符数"口径一致 |
| 原文 | 折叠态最多 2 行，超出截断；点击整条展开全文，再次点击收起 |
| 复制 | 条目内提供复制按钮，复制该条原文 |

**分页**：每页 20 条，滚动到底或点「加载更多」追加；显示「已加载 20 / 共 128」。

**异常与空态**

- 该文档 0 切片 → 提示"该文档没有可用切片，请重新上传"。
- 加载失败 → 抽屉内展示原因与「重试」，不清空已加载内容。

### FR-04 知识库对话

**目的**：得到基于知识库的答案，并能立刻核对答案引用了什么。

**布局**：单栏对话流，正文列最大宽度 760、左对齐（不居中于整页），右侧为 FR-05 侧栏。顶部标题「知识库对话」+ 一行范围说明（当前知识库 N 份文档 / M 切片）。

**提问**

- 输入框为自适应高度多行框，Enter 发送、Shift+Enter 换行；空内容不发送。
- 发送后用户气泡固定展示问题文本，输入框禁用，直到流程结束。
- 回答流式到达期间，来源先于正文出现：正文位置先显示「正在引用 N 份资料」，随后逐字渲染答案。
- 流式期间显示「停止」按钮；点击后立即中断接收，已生成内容保留并在气泡末尾标注「已停止」；输入框恢复可用。

**引用**

- 回答正文中的【来源N】必须渲染为可点击芯片（同色系、带编号），点击后定位并展开 FR-05 侧栏中编号为 N 的来源。
- 芯片编号与侧栏来源编号严格一致；编号不存在（模型写错）时降级为纯文本，不报错。

**单轮语义（重要）**：每次提问独立成一次问答，历史气泡仅作记录展示，**不参与**本次回答。界面上不提供"新会话"按钮；刷新页面即清空。此限制不需要写在使用者可见的文案里，但实现时不得在前端伪造"记忆"。

**边界与异常**

| 情形 | 表现 |
|---|---|
| 未召回任何切片 | 提示"资料库中没有检索到相关内容，请先上传并入库文档"，用普通提示样式，不用错误样式；同时侧栏显示"未召回" |
| 模型超时 / 服务不可用 / 熔断 | 已到达的来源保留可查看；答案区展示服务端可读原因，并提供「重试」（重试＝同一问题重新提问，产生新的一次问答） |
| 用户停止 | 见上；不标记为失败 |
| 网络中断 | 展示"连接中断"，提供重试；已渲染内容不丢 |

### FR-05 检索过程侧栏

**目的**：回答可信度的证据面。让使用者看出"这句答案是被哪几条切片、以什么方式撑住的"。

**位置与形态**

- 对话框右侧，宽 300，默认展开；顶部有收起按钮，收起后为 40 宽的竖条，点击展开。
- 视口宽度小于 1280 时默认收起，正文列优先。

**内容结构（按系统真实阶段，顺序固定）**

1. **双通道召回**：分别给出向量通道召回条数、关键词通道召回条数、双通道同时命中的条数。
2. **融合排序（RRF）**：展示融合后的顺序与分数，注明"两通道按排名融合，不偏袒任一通道"。
3. **送入上下文**：最终进入回答生成的条数（与正文引用编号数一致）。
4. **来源明细**：逐条列出，字段为编号、文档名、章节路径、指标（向量距离 / 关键词命中数 / 是否双通道 / 融合分数）、原文摘要（2 行截断，可点击展开）。

**规则**

- 侧栏只反映**最近一次**提问的检索结果；旧轮次的来源通过气泡内引用芯片点击时以浮层/回填方式查看（历史数据保存在前端内存，不做持久化）。
- 侧栏**不得**出现"查询改写""重排""top-k 重排"等系统并不存在的阶段。
- 无召回时侧栏整体显示"未召回"，不展示空的分阶段骨架。
- 数字单位固定：向量距离保留 3 位小数，融合分数保留 5 位小数，命中数为整数。

### FR-06 导航与整体布局

- 左侧固定导航（宽 224）：顶部产品名与"知识库 · 内部使用"；两项主导航「文档管理」「知识库对话」，当前项高亮；底部知识库概览卡（文档数、切片数、最近入库距今）。
- 主区顶部为面包屑（知识库 / 当前页名），右侧不放全局搜索（无此能力），文档页的过滤框见 FR-02。
- 两页共享同一套页头与留白规范；对话页为 `正文 1fr + 侧栏 300` 的网格，文档页为流式宽度 + 抽屉覆盖。
- 不提供登录、用户菜单、设置入口。

## 5. 共享规则与异常

**危险操作**：覆盖重建与删除文档都必须二次确认，文案必须写明影响的切片数量与"不可恢复"。确认前的操作不得发出任何请求。

**错误展示**：一律展示服务端返回的可读原因原文，不吞成"操作失败"；网络/超时类提供重试，参数类就地提示且不提交。

**加载态**：列表首屏用骨架或占位行；抽屉分页用"加载更多"；对话流式期间禁用重复提交；上传为阻塞等待态（见 FR-01）。

**空态**：三处必须有——无文档、文档无切片、本次未召回。

**数字与时间口径**：切片数、字符数用千分位；时间精确到分钟；"距今"用"12 分钟前 / 3 小时前 / 2 天前"，超过 7 天显示日期。

**键盘**：对话框 Enter 发送 / Shift+Enter 换行；抽屉 Esc 关闭；列表过滤框聚焦时不劫持方向键。
